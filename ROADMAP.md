# ROADMAP.md

## Purpose

This document defines the implementation sequence for Pablo Dorin's
professional portfolio and the Endpoint technology blog.

Development must proceed in small, reviewable phases.

Codex must not implement the entire portfolio at once.

Each phase must:

1. have a clear objective;
2. modify only the necessary files;
3. produce a functional result;
4. be reviewed before continuing;
5. pass lint and production-build validation.

## Approved stack

The portfolio uses:

- React;
- JavaScript;
- JSX;
- HTML;
- CSS;
- Vite;
- npm;
- Git;
- GitHub.

Do not introduce TypeScript.

Do not add a Java or Spring Boot backend to the portfolio itself.

Java and Spring Boot must be represented through:

- professional experience;
- projects;
- repositories;
- case studies;
- architecture explanations;
- technical articles.

## Phase 5 — Theme system and restrained motion

### Goal

Complete the light and dark themes and introduce controlled visual motion.

### Theme tasks

- Detect the operating-system preference on the first visit.
- Add manual theme selection.
- Persist the selected theme in local storage.
- Prevent incorrect theme flashing when practical.
- Validate all colors in both themes.
- Verify technology logos in both themes.

### Parallax tasks

Add subtle parallax only to approved decorative elements:

- hero Git-history branches;
- selected commit nodes;
- selected project imagery;
- selected Endpoint headers.

### Motion rules

- Keep text stable.
- Keep navigation stable.
- Keep buttons stable.
- Use transform-based movement.
- Avoid layout recalculation where possible.
- Do not use scroll hijacking.
- Do not use parallax in every section.
- Disable or strongly reduce parallax on mobile.
- Disable non-essential motion when
  `prefers-reduced-motion: reduce` is active.

### Performance requirements

- Avoid unnecessary scroll-event work.
- Use `requestAnimationFrame` only when required.
- Avoid continuous updates when the visual is outside the viewport.
- Preserve smooth scrolling performance.

### Validation

Verify:

- light theme;
- dark theme;
- theme persistence;
- operating-system preference;
- reduced-motion behaviour;
- mobile performance;
- readability with motion disabled.

Run:

    npm run lint
    npm run build

### Deliverable

A complete theme system with subtle and accessible visual depth.

## Working rule for Codex

Codex must work on only one approved phase at a time.

Before implementing a phase, Codex must:

1. summarize the objective;
2. identify the files to create or modify;
3. state its assumptions;
4. explain any proposed dependency;
5. wait for approval when the change alters the approved architecture.

After implementing a phase, Codex must:

1. list all changed files;
2. summarize the implementation;
3. run `npm run lint`;
4. run `npm run build`;
5. report all errors honestly;
6. identify any incomplete item;
7. stop before beginning the next phase.
